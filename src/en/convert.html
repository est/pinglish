01 / 03

Three modes.

One mapping, three directions. The reverse is reversible, not guesswork.

MODE 01

Hanzi → Pinglish

pinyin-pro segments the sentence and chooses readings for polyphonic characters; each syllable is then mapped. Example: 薛 → hve1.

MODE 02

Pinyin → Pinglish

Accepts pinyin with tone marks or digits. ü, iu/ui/un, j/q/x and zero initials are rewritten by rule. Example: lü3 → lv3.

MODE 03

Pinglish → Pinyin

Uses the zero-collision table of 407 syllables in reverse. Output tone digits or tone marks. Example: gvn1 → jūn.

03 / 03

It is not perfect.

What the converter can do, and what it cannot, should be clear from the start.

CAN

Deterministic mapping

The Pinglish form of a syllable is looked up, not guessed. 407 syllables, zero collisions. The same pinyin always produces the same Pinglish, and the reverse holds.

CANNOT

Decide the reading for you

Polyphonic characters depend on pinyin-pro's context model. 重庆 becomes chóngqìng, but 重 may be zhòng elsewhere. Tone sandhi, erhua and neutral tone follow the dictionary, not your local speech.

CAN

Preserve syllable boundaries

An apostrophe is inserted only when needed. Xi'an → hi1'an1, xian → hien1. Reverse parsing prefers the longest valid syllable.

CANNOT

Replace language planning

A spelling scheme does not solve education, publishing, passports, input methods, international standards or name conventions. Those are the real reasons pinyin is hard to change.

Technical note

Chinese conversion uses pinyin-pro 3.29.5 (MIT), bundled locally; no external API is called. The Pinglish engine (assets/js/pinglish.js) and the syllable table (assets/data/syllables.json) are part of this project. If you find a mapping error or a missing syllable, please open an issue.
