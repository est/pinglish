01 / 03

三种模式。

同一套映射，三个方向。反向是可逆的，不是猜的。

MODE 01

汉字 → Pinglish

先用 pinyin-pro 做分词和多音字判断，再把每个音节映射成 Pinglish。例：薛 → hve1。

MODE 02

拼音 → Pinglish

接受带调号或带数字的拼音。ü、iu/ui/un、j/q/x、零声母都会按规则重写。例：lü3 → lv3。

MODE 03

Pinglish → 拼音

用 407 个音节的零碰撞映射做反向查表。可以输出数字声调，也可以输出带调号的拼音。例：gvn1 → jūn。

03 / 03

它不完美。

转换器能做的，和不能做的，最好一开始就说清楚。

能

确定性映射

音节的 Pinglish 形式是查表得到的，407 个音节零碰撞。同一个拼音永远得到同一个 Pinglish，反过来也一样。

不能

替你决定读音

多音字依赖 pinyin-pro 的上下文判断。「重庆」会读 chóngqìng，但「重」在别的句子里可能读 zhòng。变调、儿化、轻声也按词典处理，不一定等于你所在地区的口语。

能

保留音节边界

撇号只在可能混淆时插入。西安 → hi1'an1，先 → hien1。反向解析会优先匹配最长音节。

不能

替代语言规划

一套拼写方案不解决教育、出版、护照、输入法、国际标准和人名惯例。那些才是拼音真正难改的地方。

技术说明

中文转换使用 pinyin-pro 3.29.5（MIT），随站点本地打包，不请求外部 API。Pinglish 引擎（assets/js/pinglish.js）与音节表（assets/data/syllables.json）是本项目的一部分。若发现映射错误或未覆盖的音节，请开 issue。
